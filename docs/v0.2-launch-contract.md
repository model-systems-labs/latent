# Latent v0.2 launch contract

Status: **frozen release target; implementation incomplete; not yet released**

Latent v0.2 is an open-source, agent-friendly reference platform for building
learning products. It includes courses, browser IDE exercises, flash cards, and
programming practice. The included LLM Systems curriculum is the full reference
implementation.

The launch promise is:

> **Build your own learning platform with agents.**
>
> Latent is an opinionated, open-source framework for courses, browser IDE
> lessons, flash cards, and programming practice. Use any coding agent to
> extend it; the included LLM Learning course shows what a complete platform
> can become.

The phrase "supports" does not mean that every surface is a remotely loadable
plugin. v0.2 deliberately has two extension modes:

1. **Portable content:** untrusted declarative data that can be authored by a
   person or agent, validated, inspected, and hosted independently.
2. **Trusted platform source:** application code, behavioral contracts, and
   runtime adapters added to a repository fork, reviewed, tested, and compiled
   before deployment.

See
[ADR-0001: Portable content and trusted executable extensions](./decisions/0001-portable-content-and-trusted-extensions.md)
for the security and dependency decision behind these modes.

## Supported surfaces

| Surface | v0.2 status | Supported workflow | Boundary |
| --- | --- | --- | --- |
| Learning Packs: lessons, quizzes, and flash cards | Stable public format | Author JSON, validate it with the Course Kit CLI, build a standalone site and integrity-bound feed, and host it on any static server | Declarative, text-rendered, and non-executable |
| Question Groups: programming practice | Required for release; currently preview | At release: author JSON, run the full Course Kit validator, build a self-hosted practice player, or import it into a trusted platform; JSON Schema alone is not the publication gate | The reviewed built-in library runs at `/practice`; a hosted library never grants an unrelated Latent deployment remote runtime authority |
| Browser IDE and executable courses | Open-source reference implementation | Clone or fork the repository, add trusted source plus host-owned checks, run the repository validation gate, and deploy the resulting application | Browser Lab and Python Lab are source-first workspace packages, not stable remote plugin APIs |
| Agent integration | Stable for Learning Packs; Question Group workflow required for release; repository-level for platform changes | Existing skills author, review, and publish Learning Packs; v0.2 adds the equivalent full-validator workflow for Question Groups; coding agents may modify a fork under the same review and CI rules as a human contributor | Agents act during authoring and build, never as implicit learner-runtime authorities |
| Learning Pack self-hosting | Stable | Host the generated site and integrity-bound feed on any conforming static server without a Latent account | A central directory or managed service is optional |
| Reference application deployment | Cloudflare/Sites implementation | Run the repository locally or deploy its current Worker and D1 build through the documented Sites path | The full application does not yet claim a provider-neutral host-anywhere production contract |

Question Groups remain a preview during development. Before the
`course-kit-v0.2.0` tag, their durable authorship, licensing, provenance,
source-grounding, learning-objective, extension, CLI, publishing, progress,
and player contracts must be completed. The candidate schema may change while
that work is in progress. The v1 URL must not be published until the complete
contract passes the release gate; tagging v0.2 then freezes those versioned
schema bytes.

## Current release truth

The machine-readable source of truth is
[`docs/release-status.json`](./release-status.json).

- `course-kit-v0.1.0` is the latest published Course Kit release.
- The v0.1.0 GitHub tarball is the current registry-independent installation
  path. Course Kit is not yet published under the `@latent` npm scope.
- The repository source is preparing Course Kit v0.2.0. A package version in
  source is not proof that its tag, tarball, npm package, or immutable schema
  URL exists.
- A Sites deployment may demonstrate unreleased repository code, but it does
  not change the published package contract.

## v0.2 release gates

The release is not complete until all of these statements are true:

- The release commit is on `main`, and required CI passes for that exact
  commit.
- The `course-kit-v0.2.0` tag points to that exact commit.
- Every documented install command succeeds in an empty directory.
- The GitHub release contains the exact package tarball and its SHA-256
  checksum.
- The versioned Learning Pack, feed, and Question Group schema URLs return the
  committed bytes.
- Documentation distinguishes stable Learning Pack workflows, released Question
  Group workflows, and trusted repository extensions.
- Question Groups include the release-ready authorship, licensing, provenance,
  objective, extension, CLI, self-hosted player, and progress contracts; the
  checked-in schema, package schema, and published v1 bytes are identical.
- The documented agent-authoring workflow can create, fully validate, and
  package a Question Group library without granting runtime authority.
- The reference deployment identifies the exact released source commit.
- `npmState` remains `unpublished` for v0.2, no documentation advertises an npm
  package, and the GitHub release tarball remains the installation path.

Release preparation is a separate commit: move and rewrite the changelog
entries into a dated v0.2 section so they describe released—not candidate or
unreleased—contracts, update every pinned Course Kit URL to v0.2.0, merge that
commit to `main`, set `docs/release-status.json` to the exact released version
while keeping `npmState` as `unpublished`, remove the preview, `404`, and
unreleased markers from the generated Question Group guides and `llms.txt`,
regenerate their packaged and public copies, and only then create the tag. The
tag-time release check rejects stale release URLs and pre-release status
language. npm publication is intentionally deferred to a later, separately
versioned release contract.

## Reference application launch gate

The Course Kit tag publishes package and schema artifacts. The public reference
application is a separate Sites release. Before announcing v0.2:

- Build and validate the exact tagged source.
- Push that exact commit, save a Sites version whose `commit_sha` matches it,
  and deploy only that saved version.
- Verify the Sites version provenance reports the tagged commit.
- Verify the rendered homepage after client hydration, not only its
  server-rendered defaults. Saved `/api/site-copy` values must be empty or match
  the frozen launch hook.
- Verify the live metadata, README hook, supported-surface table, and release
  status all describe the same contract.

## Explicit non-promises

v0.2 does not promise:

- arbitrary remotely loaded executable plugins;
- automatic execution of a hosted Question Group library by Latent;
- a hostile-code Python security sandbox;
- a model provider or hosted agent at learner runtime;
- a required registry, marketplace, account, or central repository;
- a stable standalone Browser Lab or Python Lab package API; or
- a provider-neutral production adapter for the complete reference
  application; or
- the optional managed creator service, billing, collaboration, or
  certification.
